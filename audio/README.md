# audio/ — тестовый материал

Сюда кладутся записи для прогонов. **Содержимое папки не попадает в git**
(`.gitignore`), в репозитории живёт только этот README — чтобы папка
существовала в свежем клоне и не приходилось вспоминать, куда класть файлы.

Записи авторские и тяжёлые (один «Прометей» — 52 МБ), место им на диске,
а не в истории.

## Что стоит сюда положить

По CLAUDE.md прогоны делались на этих записях, и обе нужны, если трогать
анализ, — проверять надо **обе**, не только ту, что жалуется сейчас:

| файл | зачем | что уже измерено |
|---|---|---|
| Симфония № 1 ми мажор (Ашкенази), ~7 мин | медленная, тихая Lento | 144 сегмента → 21 блок; тональность E; вспышек 0 |
| «Прометей» (Ашкенази), 21:42 | плотная, длинная | 180 сегментов → 26 блоков; муз. 0:01–21:36; ~1.4 вспышки/мин |
| Партита № 1 Баха, Corrente e Double (Коган) | соло-скрипка, двойные ноты | на t≈148.75 с — чистая квинта D+A, две лампы + золотая вспышка |

Имена файлов не важны — ничего в коде на них не завязано. Исключение:
идея «парсить тональность из имени файла» из списка нереализованного
(CLAUDE.md, пункт 1) — если до неё дойдёт, имена станут значимы.

## Грабли, уже оплаченные (CLAUDE.md, раздел «Проверено эмпирически»)

- **Синтетический эталон строить на реальной длительности трека.** Сжатый
  до 120 с эталон дал обманчивые 96.7% верных кадров, пряча мерцание —
  37 смен ноты вместо 6 настоящих. На реальных ~22 минутах это вскрылось.
- **Считать число смен состояния, а не только процент верных кадров.**
  Процент кадров мерцание не ловит.
- **WAV генерировать через `soundfile`/libsndfile, не через модуль `wave`.**
  Питоновский `wave` даёт заголовок, который `<audio>` проигрывает, а
  `AudioContext.decodeAudioData` отклоняет с `EncodingError`.
- **Замеры скорости — на свежей вкладке каждый раз.** Долгоживущая вкладка
  с историей прогонов TF.js копит незачищенные тензоры; именно так родилось
  ложное «7.3x медленнее реального времени», которое при перепроверке
  оказалось 0.3x.
