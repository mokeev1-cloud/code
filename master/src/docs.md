# Мастер предпродажной подготовки юрлиц — документация

Один HTML-файл, работает с диска без сервера и интернета. Все вычисления — в браузере, данные никуда не отправляются. Движок расчета (зачеты, уступки, переводы долга, готовность к ликвидации) — из инструмента «ВГО: уступки, зачеты, ликвидация»; поверх него добавлены пошаговый мастер, внешние шаблоны Word и **дело** — реестр выпущенных документов, который не дает запутаться в номерах, редакциях и подписях.

## 1. Шесть шагов

1. **Данные.** Перетащите всё сразу: выгрузки 1С, реестр ЮЛ, реквизиты, «Недогруз», файл дела (.json), шаблоны (.docx). Вид файла определяется по шапке. Кнопка «Показать на демо-данных» загружает выдуманный набор.
2. **Параметры.** Организации пакета и их префиксы, Консолидатор, даты, статусы реестра, счета-долги, получатель внешних долгов, пороги. Настройки запоминаются в браузере (без ИНН и наименований — только хэши).
3. **Готовность.** Вывод по каждому ЮЛ: Можно / Условно готово / Пауза / Не готово / Нет данных, причина, что сделать, срок и план мероприятий.
4. **Внутри группы.** Зачеты и уступки между организациями группы; остаток уступает кредитор на Консолидатора; цена уступленной дебиторки гасится зачетом (ЗЦ).
5. **Внешние долги.** Зачет с внешним контрагентом, уступка внешней дебиторки (+ уведомление должнику), перевод внешней кредиторки с согласия кредитора.
6. **Выпуск и подпись.** Сверка расчета с делом, выпуск пакета на подпись, статусы подписания.

Шаги 3–5 только показывают расчет. Документы создаются на шаге 6.

## 2. Как не запутаться: дело

Проблема: документов сотни, подписание идет неделями, данные 1С меняются. Если каждый раз пересчитывать «с нуля», номера съезжают, а подписанное расходится с новыми данными.

Решение — **дело** (файл `Дело … .json`). В нем у каждого документа есть:

| Поле | Смысл |
|---|---|
| ключ | устойчивая «личность» операции: зачет — пара сторон; уступка — «цедент → должник». Не зависит от порядка организаций и от сумм |
| номер | присваивается один раз и **никогда не меняется и не переиспользуется** |
| редакция | растет при перевыпуске (в имени файла — `_ред2`) |
| статус | подготовлен → на подписи → подписан (или аннулирован) |
| отпечаток | хэш содержания (суммы, состав требований, договоры-основания, порядок расчетов) |
| реквизиты и шаблон | отпечатки реквизитов сторон и шаблона, по которым выпущен документ |
| история | кто что когда менялось |

При каждой загрузке данных расчет сверяется с делом. Каждая операция получает одно из состояний:

| Состояние | Что значит | Что делать |
|---|---|---|
| **Новый** | в деле нет такой операции | выпустить — получит новый номер (после максимального занятого) |
| **Без изменений** | отпечаток совпал | ничего; в выпуск не попадает |
| **Изменился** | документ еще не подписан, данные изменились | перевыпуск: **тот же номер, новая редакция**; прежнюю редакцию отозвать |
| **Расхождение** | документ подписан, а данные изменились | решение за вами: «принять как есть» (запоминается) или «заменить новым документом» (старый аннулируется, выпускается новый номер) |
| **Исчез** | по данным документ больше не нужен | аннулировать (не подписывать) или оставить |
| **Исчез, подписан** | подписанный документ больше не нужен по данным | оставить в силе или пометить аннулированным (может понадобиться документ о расторжении) |

В колонке «Что изменилось» причина сформулирована человеческим языком: «сумма 1 200 000,00 → 1 350 000,00 (+150 000,00)», «сч. 60: 500 000,00 → 650 000,00», «изменились реквизиты: Цедент», «обновлен шаблон документа».

### Правила, на которых все держится

- **Файл дела нужно сохранять** после каждого выпуска и каждой смены статуса (индикатор в шапке подсвечивается, закрыть вкладку без сохранения браузер не даст). В дело входят ИНН и наименования — это ваш рабочий файл, держите его рядом с данными. По желанию на шаге 1 можно включить страховочную копию в браузере.
- Порядок обработки организаций пакета запоминается в деле: документ между двумя организациями формируется «с точки зрения» той, что обработана первой, и перестановка на экране не меняет формулировки уже выпущенных документов.
- Даты. Сумма, состав и реквизиты определяют отпечаток; **даты документов и срок оплаты — нет**. Перевыпуск по умолчанию сохраняет дату прежней редакции (параметр на шаге 2), чтобы пакет не «разъезжался».
- Выпуск включает только отмеченное: новые и изменившиеся. «Без изменений» можно выгрузить повторно, отметив вручную.
- Проводки бухгалтеру по выпуску — только по документам этого выпуска, с пометкой «перевыпуск, ред. N: прежнюю, если проведена, сторнировать». Полная сводка по всему расчету есть на шаге 4.

## 3. Что получаете на выходе

Архив `Выпуск N от дд.мм.гггг.zip`:

- `Документы на подпись/{Организация}/{Контрагент}/…docx` — удобно отправлять контрагенту папкой (можно отключить — тогда структура по видам документов);
- `Реестр документов.xlsx` — листы «Реестр», «По контрагентам» (что у кого на подписи), «Сверка», «Выпуски»;
- `Бухгалтеру — проводки по выпуску N.xlsx`;
- `Памятка по выпуску.txt` — что отправить, что заменить, замечания;
- обновленный файл дела.

## 4. Шаблоны договоров (Word)

Шаблоны лежат отдельными файлами и правятся юристами как обычные документы Word. Откройте панель «Шаблоны» (шапка): загрузите правленые файлы — они сохраняются в браузере и применяются сразу. Без загрузки используются встроенные тексты. Образцы всех пяти шаблонов можно скачать там же (кнопки «Скачать образец»).

| № | Шаблон | Подписывают |
|---|---|---|
| 1 | Договор уступки (внутригрупповой) | цедент, цессионарий, должник |
| 2 | Договор уступки (внешний должник) | цедент, цессионарий (должнику — уведомление) |
| 3 | Уведомление должнику об уступке | цедент |
| 4 | Соглашение о зачете (в т.ч. зачет цены уступки) | стороны зачета |
| 5 | Соглашение о переводе долга | кредитор, первоначальный и новый должник |

Вид определяется по номеру в начале имени файла («1 …», «2 …») или по содержанию. Метки: `{{Цедент.Наименование}}`, `{{Дата.Прописью}}`, `{{Сумма.Прописью}}`, `{{Порядок расчетов}}`, строки таблицы с `{{п.№}} {{п.Основание}} {{п.Содержание}} {{п.Сумма}}` повторяются по числу требований; условный текст `{{если АВАНС}}…{{/если}}` (также ЗАЙМ, АДРЕС, `НЕ`) — в пределах одного абзаца, нумерация пунктов выравнивается автоматически. Полный перечень — в панели «Шаблоны» → «Какие метки бывают».

При загрузке шаблон проверяется: неизвестные метки, несбалансированные `{{если}}`, отсутствие обязательных меток (номер, таблица, порядок расчетов). Кнопка «Пример на демо-данных» формирует документ из выдуманных данных — чтобы юристы видели результат, не загружая реальные выгрузки.

**Шаблон и дело.** Дело запоминает отпечаток шаблона, по которому выпущен документ. Если юристы обновили шаблон, неподписанные документы получают пометку «обновлен шаблон» (перевыпуск в новой редакции), на подписанные это не влияет.

## 5. Ограничения

- Браузер не может сам читать файлы рядом с HTML (`file://`), поэтому шаблоны и дело загружаются выбором или перетаскиванием.
- Подписанный документ нельзя «изменить» — юридически нужен отдельный документ (допсоглашение/расторжение). Шаблонов для них в инструменте нет; мастер лишь показывает, что подписанное разошлось с данными.
- Если соглашение о зачете цены (ЗЦ) выпускается позже договоров уступки, дата в тексте ЗЦ — его собственная; мастер предупреждает, когда даты расходятся.
- Внешние документы нумеруются с префиксом `В` + префикс организации (например, `ВА-Ц-01`), чтобы номера разных организаций не пересекались.

## 6. Разработка

Исходники — в папке `master/` репозитория: `src/engine/*` (движок), `src/case.js` (дело), `src/app-*.js`, `src/style.css`, `src/index.html`. Сборка — `python3 master/build.py` (результат `master/master.html`). Тесты — `node master/tests/case.test.js` (дело и устойчивость нумерации) и `node master/tests/engine.test.js` (самопроверка движка + шаблоны). В браузере самопроверка — «?» → «Самопроверка движка». Реальные данные в код и документацию не попадают.
