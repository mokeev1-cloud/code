
# ВГО: уступки, зачеты, ликвидация — документация проекта

Документ встроен в сам HTML-файл (блок `script#project-docs`). Его задача — позволить продолжить разработку в новой сессии (человеку или ИИ-ассистенту) без доступа к истории переписки. При любом изменении кода обновляйте этот документ.

## 0. Как начать работу с проектом

1. Откройте HTML в браузере (Chrome/Edge/Firefox) — он работает с диска (`file://`), без сервера и интернета.
2. Вкладка «Документация» → кнопка «Самопроверка»: прогоняет движок на синтетических данных. Все проверки должны быть «OK».
3. Чтобы править код, извлеките модули в отдельные файлы (раздел 4), правьте, соберите обратно, снова запустите самопроверку.
4. Реальные данные пользователя в код и документацию **не попадают никогда** (раздел 2).

## 1. Назначение

Инструмент для бухгалтерии/финансовой службы группы компаний. Работает с внутригрупповыми (ВГО) расчетами по данным 1С:Бухгалтерия предприятия 3.0.

Решаемые задачи — **три независимые ветки (режима) интерфейса, их нельзя смешивать** (требование пользователя):

1. **Свертывание ВГО — договоры** (движок Engine2 + EngineAcc): зачеты и уступки внутри группы на Консолидатора.
2. **Ликвидация — договоры по внешним долгам** (EngineExt): зачет с внешним контрагентом, уступка внешней дебиторки получателю (с уведомлением должника), перевод внешней кредиторки на получателя (с согласия кредитора).
3. **Ликвидация — готовность и план мероприятий** (EngineLiq): только анализ и план, документов не формирует; в «что сделать» ссылается на ветки 1 и 2.

Подробнее:

- **Расчистка ВГО-долгов организации** (подготовка к продаже/ликвидации): встречные требования зачитываются, остатки передаются по договорам уступки единому кредитору группы — **Консолидатору**. На выходе: таблица Excel, пакет договоров/соглашений в Word (.docx) с реквизитами, проводки для 1С.
- **Пакет по нескольким организациям сразу** с корректной связкой: операция между двумя организациями пакета оформляется один раз, сквозная нумерация с префиксами.
- **Готовность ЮЛ к ликвидации**: по списку ЮЛ — вывод «Можно / Условно готово / Пауза / Не готово / Нет данных», причина, что сделать, срок, динамика; для каждого ЮЛ — план мероприятий (расчистка + юридическая ликвидация с датами).
- **Внешние долги ликвидируемого ЮЛ**: кому и каким документом передать (ветка 2).
- **Сводка для бухгалтера**: одна страница сводки + проводки «Операция (бухгалтерский учет)».

## 2. Принципы и требования (обязательны)

- **Только локально.** Один самодостаточный HTML. Никаких серверов, CDN во время работы, внешних API и нейросетей. Данные не покидают компьютер.
- **Обезличенность кода и документации.** В коде нет ИНН, наименований, ФИО, сумм, адресов из реальных данных. Роли определяются **по реестру**: единый кредитор — ЮЛ со статусом «Консолидатор». Значения по умолчанию в интерфейсе — нейтральные (первая организация по алфавиту, пустой пакет, цессионарий — из реестра).
- **ИНН и реквизиты не хранятся в явном виде** нигде, кроме загружаемых пользователем файлов: ни в коде, ни в документации, ни в сохраняемых настройках (там — хэши).
- **Результат «как от человека».** Excel не перегружать (2–5 листов), без «воды» и служебных пояснений на листах. Документы — нормальный деловой русский.
- **Логика долга:** встречные требования с одним контрагентом сначала зачитываются; остаток **уступает кредитор**. Форма требования определяется счетом и знаком сальдо (поставка / аванс / заем / прочее).
- **ИНН — главный ключ.** Сопоставление по наименованию — только запасной путь, с пометкой «проверьте».
- **Приоритет свежих данных**; неоднозначности показываются, а не скрываются.
- Перед деструктивными действиями (удаление файлов и т. п.) — спрашивать пользователя.

## 3. Входные данные

### 3.1. Анализ субконто «Контрагенты» (основной источник)

БП 3.0 → Отчеты → Анализ субконто. Вид субконто «Контрагенты», без отбора по счетам, показатели только БУ, доп. поле «ИНН». Группировки Excel (outline) задают уровни.

Синтетический пример (уровень — в первой колонке):

| Уровень | Колонка A | ИНН | Сальдо нач. Дт | Кт | Обороты Дт | Кт | Сальдо кон. Дт | Кт |
|---|---|---|---|---|---|---|---|---|
| 0 | Организация А ООО | 1000000001 | | | | | | 500 |
| 1 | Контрагент В ООО | 1000000003 | 300 | | | | 300 | |
| 2 | 62 | | 300 | | | | 300 | |
| 1 | Контрагент Г ООО | 1000000004 | | 200 | | | | 200 |
| 2 | 60 | | | 200 | | | | 200 |

- Уровень 0 — организация (книга), 1 — контрагент, 2+ — счет. Строки «Итого», «Счет», «Контрагенты», «Организация» пропускаются.
- Колонки находятся по шапке: «Сальдо на конец периода» (Дт = эта колонка, Кт = следующая); начало и обороты — смещения −4/−3 и −2/−1 от нее.
- Ниже контрагента могут идти договоры (любой текст, не код счета) — запоминаются в `cp.contracts`, строки валюты (`CNY`, `USD`) пропускаются. Суммируются только строки счетов одного уровня (первого встреченного), чтобы не задвоить счет и субсчет.
- Период берется из заголовка: «3 квартал 2026 г.» (3 мес.), «9 месяцев 2026 г.», «за 01.01.2026 - 30.09.2026», «2026 г.» (12). Дата остатков — конец периода.
- **Старый формат** (одна организация без группировок, без ИНН) поддерживается через `Engine.parseAnalysis`; там же — ручная разметка колонками «КЗ ВГО» / «ДЗ ВГО» (сумма может стоять на соседней строке — привязывается к контрагенту с тем же сальдо).
- Несколько файлов: организации объединяются по ИНН. Если организация уже есть — дописываются новые контрагенты и недостающие счета, существующие не задваиваются (полные копии отчета пропускаются как повторы).
- **Важно:** выгрузка с отбором по комментарию «ВГ» может не содержать часть ВГО-контрагентов — нужны выгрузки **без отбора**, ВГО определяется по реестру.

### 3.2. Реестр ЮЛ (Excel)

Первая строка — шапка. Колонки ищутся по названию: «Наименование», «Статус участия», «ИНН», «ЗДС», «… гос. контрактов», «Название в 1С», «Примечание», «Комментарий», «Алиасы контрагента».

Статусы (регистр не важен):

| Статус | Смысл в движке |
|---|---|
| Консолидатор | единый кредитор группы; всегда в работе; цессионарий по умолчанию |
| Транзит, Обнуляем, Обнуляем приоритет | в работе по умолчанию (галочки на странице) |
| Запрещено, Чужой | не в работе; расчеты с такими ВГО **блокируют** ликвидацию |

Колонка про госконтракты сейчас только справочная.

### 3.3. Реквизиты (Excel, блочный формат)

Пары «ключ — значение» в колонках A/B; блок начинается строкой «Полное наименование». Используются: Полное наименование, ИНН, Код КПП, Юридический адрес, Расчетный счет, Банк, БИК, Корр.счет, Директор / Генеральный директор / Руководитель (последнее трактуется как «Генеральный директор»). Индекс — по ИНН.

### 3.3а. Регистр бухгалтерии «Остатки и обороты» с ИНН (рекомендуемый источник)

Выгрузка таблицы «Остатки и обороты» регистра «Журнал проводок (бухгалтерский и налоговый учет)» (консоль запросов / универсальный отчет): **все организации базы и все счета одним файлом**. Распознается по строкам «Регистр бухгалтерии» / «Остатки и обороты» / «кон. ост. Дт» в шапке.

- Группировки (уровни структуры Excel): 0 — организация (**без ИНН**), 1 — счет/субсчет, 2 — «Субконто 1, ИНН» (наименование и ИНН через запятую; у не-контрагентов ИНН пустой), 3 — субконто 2 (для 58/60/62/66/67/76 — договор; документы с временем «0:00:00» пропускаются).
- Колонки ищутся по заголовкам: нач. ост. Дт/Кт, оборот Дт/Кт, кон. ост. Дт/Кт. Лист может начинаться не с первой строки — `readBook` выравнивает уровни по `!ref`.
- В контрагенты берутся только счета 19, 58, 60, 62, 66, 67, 76; остальное (01, 03, 50, 51, 68, 70, 71, 73, 75, 80 …) — в итоги организации `org.totals[счет] = [нач, Дт, Кт, кон]` (используется 03 для ликвидации).
- ИНН организации подбирается `Engine2.fillOrgInn(merged, reg, req)` по наименованию: реестр (точное имя, затем ключ наименования), затем реквизиты. Не найденные — `merged.noInn` (показываются красным).
- Архивные копии вида «Организация (до 31.12.2023)» к ИНН **не привязываются** (`merged.archive`, с суммой остатков) — иначе они смешаются с действующей организацией.
- Одна выгрузка = **одна база 1С**. Если та же организация есть в выгрузках двух баз — остатки складываются (`merged.multiBase`).
- Период: «Период: 01.07.2026 - 30.09.2026» → остатки на 30.09, обороты за квартал (критерий отгрузок). Если конец периода в будущем (например, «по 31.12»), остатки фактически на сегодня, а обороты — с начала периода; это выводится примечанием (`merged.notes`).

### 3.4. Плановые источники (еще не поддержаны)

- **Универсальный отчет** (БП 3.0 → Отчеты → Универсальный отчет): Регистр бухгалтерии «Журнал проводок (бухгалтерский учет)» → «Остатки и обороты»; группировка Организация → Счет → Субконто1 → Субконто2; показатели — сальдо нач./кон. Дт/Кт, обороты. Дает субсчета (60.01/60.02, 62.01/62.02, 76.АВ), договоры (Субконто2 на 60/62/76), работников, деньги, имущество, налоги, капитал. Попробовать доп. поле «Субконто1.ИНН».
- Анализ субконто «Работники организаций» (70, 71, 73, 76).

Ограничения БП 3.0, выясненные на практике: ОСВ строится по одной организации (группировки «по организациям» нет); в анализе субконто несколько видов субконто работают только для счетов, где есть все выбранные виды; субконто «Договоры» в анализе субконто может быть недоступно.

| app | интерфейс страницы | — |

Модули движка написаны в стиле ES5 (IIFE), работают и в браузере, и в Node (`module.exports`), поэтому их можно тестировать в Node.

Извлечь модули (Node):

```
const fs = require('fs');
const html = fs.readFileSync('page.html', 'utf8');
for (const m of html.matchAll(/<script[^>]*id="([^"]+)"[^>]*>([\s\S]*?)<\/script>/g))
  fs.writeFileSync(m[1] + (m[1] === 'project-docs' ? '.md' : '.js'), m[2]);
```

Собрать обратно — заменить содержимое тегов по id тем же способом (содержимое модулей не должно включать закрывающий тег script). Тестирование в Node:

```
const E = require('./engine-core.js');
E.libs({ XLSX: require('./lib-xlsx.js'), JSZip: require('./lib-jszip.js'), petrovich: require('./lib-petrovich.js') });
require('./engine-test.js').run().then(console.log);
```

(в Node модули подключают друг друга по путям `./engine.js`, `./engine_v2.js`, `./engine_acc.js`, `./engine_liq.js`, `./engine_ext.js` — при извлечении сохраняйте под этими именами либо поправьте `require`).

## 5. Модули

### 5.1. engine-core (Engine)

- Утилиты: `s` (нормализация строки), `num`, `r2` (округление до копеек), `money` («1 234,56»), `words` (сумма прописью: «1 234,56 (Одна тысяча двести тридцать четыре) рубля 56 копеек»), `dateShort`, `dateLong` (««30» сентября 2030 г.»), `parseDate`, `quotes` (прямые кавычки → «ёлочки» с балансом).
- `nameKey(name)` → `{form, core}`: правовая форма (ооо/ао/зао/пао/ип), ядро — отсортированные слова без кавычек/скобок/знаков; «производственное объединение» → «по». Для сопоставления наименований разных написаний.
- `parseRequisites(rows)` → `{orgs, byInn}`; `parseRegistry(rows)` → `{byInn, byName, byKey, all}` (у записи: inn, name, status, key, zds, gk, note).
- `parseAnalysis(rows)` — старый формат (см. 3.1).
- `party(org, fallbackName, inn)` — сторона договора: наименование, ИНН/КПП, адрес, банк, должность и ФИО подписанта в родительном/дательном падеже (petrovich), «действующего/действующей», ИП, город из адреса (если нет — пустое поле), `intro(role)`, `dative()`, `reqLines()`.
- DOCX: `doc()` — построитель WordprocessingML (заголовок, место/дата с табуляцией вправо, абзацы с отступом, таблица реквизитов без рамок, `grid` — таблица с рамками), `docxBlob(d)` — упаковка через JSZip (минимальный набор частей: [Content_Types], _rels, document.xml, styles.xml; Times New Roman 11,5).
- Унаследованный поток одной организации (v1): `resolve`, `plan`, `buildPackage`, `buildXlsx` — сохранен для старого формата, интерфейс использует Engine2.

### 5.2. engine-cess (Engine2)

- `readBook(buf)` (SheetJS с `cellStyles` — нужны `!rows[i].level`), `parseBook(book, fileName)` → `{file, title, date, months, orgs:[{name, inn, file, cps:[{name, inn, acc:{счет: сальдо}, det:{счет:[нач, Дт об., Кт об., кон.]}, contracts?}]}]}`. Сальдо со знаком: **+ Дт (нам должны), − Кт (мы должны)** — с точки зрения организации-книги.
- `mergeBooks(books)` → `{orgs, byInn, dup, date, months, files}`.
- `listAccounts(merged, orgInn)`; `NOT_DEBT` = {19 НДС, 63 резервы, 68, 69, 70}; долговые счета — 5x/6x/7x кроме NOT_DEBT (галочки на странице переопределяют).
- `prepare(merged, req, reg, opts)` — список контрагентов организации: обязательства по счетам, исключенные счета, сальдо, **зеркало** (сальдо из книги самого контрагента, если она загружена, со сменой знака), статус, причина исключения, `include`. Правило НДС-76: сумма на 76 исключается как НДС с авансов (76.АВ/76.ВА), если без нее сальдо совпадает с книгой контрагента, а с ней — нет; без книги контрагента — если 76 равна 10/110, 20/120 или 22/122 аванса на 60/62.
- `kind(acc, amount)` — вид требования (таблица в 6.2).
- `plan(data, opts)` — зачеты, уступки, итог с консолидатором (раздел 6.3). `opts`: statuses, cessionary (реквизиты), date, payDate, payDzByOffset, prefix, external, offsetCedents.
- `runGroup(merged, req, reg, base, [{inn, prefix}])` — пакет по нескольким организациям со связкой (6.4). `base.adjust(data, opts)` — хук ручных правок интерфейса.
- `buildPackage(pl, data, opts)` → zip: `1_Зачеты/`, `2_Кредиторы … уступают требования/`, `3_… уступает дебиторку/` (+ соглашение ЗЦ). Внешние (уже оформленные в пакете другой организации) документы не генерируются.
- `buildXlsx(pl, data, opts, extraSheets)` — листы «Уступки» (строка на каждое требование), «Зачеты», «Сверка и исключения».

### 5.3. engine-acc (EngineAcc)

`postings(r)` — строки проводок для результата `runGroup`; `buildAccountantXlsx(results)` — листы «Сводка» (одна страница, колонка на организацию, порядок работы в 1С) и «Проводки 1С» (одна операция на документ). Схема — раздел 7.

### 5.4. engine-liq (EngineLiq)

- `resolveList(text, reg)` — строки списка (ИНН или наименование, нумерация допускается) → записи реестра; при нескольких кандидатах берется тот, кого нет в списке отдельной строкой; признак `ambiguous`.
- `analyze(text, merged, reg, req, opts)` → `{rows, list}` (пакетов документов НЕ строит — это ветки 1 и 2); `opts`: threshold (порог внешнего долга), shipThreshold (порог отгрузок), assignExternal, balanceDate, startDate (дата решения о ликвидации для готовых).
- Метрики строки: vgoDz/vgoKz/extDz/extKz, ship (Дт оборот 62 с не-ВГО), pay (Кт оборот 62 с не-ВГО), grossOpen/grossClose, trend, acc03, blockers, extBig, mirror.
- `plan(r, opts)` → шаги `{stage, what, where, when, state}`: «Расчистка» (блокеры, ВГО → ветка 1, внешние долги → ветка 2, имущество сч. 03) и «Ликвидация» (решение и Р15016, публикация в «Вестнике», 2 месяца на требования кредиторов, промежуточный баланс, расчеты по ст. 64 ГК РФ, ликвидационный баланс, Р16001). Для готовых — даты от startDate, для остальных — «Д + …». В интерфейсе план раскрывается по клику на строку.
- Правила вывода — раздел 6.6; `buildXlsx(res, opts)` — листы «Готовность», «План мероприятий», «Остатки по контрагентам».

### 5.4а. engine-ext (EngineExt) — ветка 2

- `prepare(merged, req, reg, {orgInn, threshold})` — внешние контрагенты = нет в реестре ЮЛ. Исключаются публичные расчеты (ФНС, УФК, СФР/ПФР/ФСС, таможня — regex `PUBLIC`) и суммы меньше порога (по умолчанию 1 000 ₽). Ручные флажки «в работе» запоминаются в `XMAN` (ключ `orgInn:inn:name`).
- `plan(data, {prefix:'В'})` → зачеты `В-З-NN` (встречные долги), уступки ДЗ `В-Ц-NN` + уведомления `В-У-NN`, переводы долга `В-П-NN`.
- Документы: уступка внешней ДЗ — двусторонняя (цедент + получатель, без подписи должника, условие об уведомлении по ст. 385 ГК РФ, 2 экз.) — `Engine2.cessionDoc(..., {external:true})`; `noticeDoc` — уведомление должнику; `transferDoc` — трехсторонний перевод долга (ст. 391–392 ГК РФ, согласие кредитора — его подпись).
- `buildPackage(pl, data, {recipient, date, payDate, payByOffset})` → zip: `1_Зачеты с внешними контрагентами`, `2_Уступка внешней дебиторки`, `3_Перевод внешних долгов`; `buildXlsx` — лист «Внешние долги».
- Интерфейс ветки 2: выбор ЮЛ, получатель (по умолчанию Консолидатор из реестра), даты, порог, опция «расчеты с получателем зачетом»; таблица с флажком «в работе» и колонкой «Документ» (какие документы будут созданы); кнопки «Таблица Excel» и «Пакет документов (zip)».

### 5.5. engine-test (EngineTest)

`dataset()` — синтетика (организации «Организация А», «Организация Б», «Консолидатор», контрагенты «Контрагент В», «Контрагент Г», «Контрагент Запрет», «Покупатель Внешний», ИНН вида 1000000001). `run()` → массив `{test, ok, info}`. Проверяет: исключения по статусу и отсутствию в реестре, консолидатора, зачеты, однократность операции между организациями пакета, обнуление ВГО проводками, долг консолидатору, нулевой финрезультат по 91, правила ликвидации, сборку docx и xlsx.

### 5.6. app (интерфейс)

Режимы (кнопки «Что делаем»): «1. Свертывание ВГО — договоры», «2. Ликвидация — договоры по внешним долгам», «3. Ликвидация — готовность и план мероприятий» (список ЮЛ можно подставить из реестра по статусам — по умолчанию «обнуляем*»), «Документация» (этот текст, самопроверка, скачать .md). ## 6. Бизнес-правила

### 6.1. Кто в работе

Контрагент организации в работе, если его ИНН есть в реестре и статус отмечен (или «Консолидатор»), и есть ненулевые долговые обязательства. Не в работе: нет в реестре (внешние), «Запрещено», «Чужой», только НДС/нули.

**Источник истины по ВГО — реестр.** Наличие книги организации в выгрузках — лишь проверка: на практике почти все книги из выгрузок есть в реестре (кроме сторонних организаций на бухгалтерском обслуживании), но заметная часть ВГО из реестра своих книг в выгрузках не имеет, а часть книг принадлежит ЮЛ со статусом «Чужой». Поэтому правило «ВГО = то, что встречается как организация в данных» неверно; расхождения в обе стороны нужно показывать (план — панель покрытия, раздел 12).

### 6.2. Вид требования по счету и знаку

| Счет | Сальдо | Вид | Формулировка требования в договоре |
|---|---|---|---|
| 60 | Дт | аванс, выданный поставщику | передача предварительно оплаченного товара либо возврат предоплаты (ст. 487 ГК РФ) |
| 60 | Кт | оплата поставленного товара | оплата поставленного товара (работ, услуг) |
| 62 | Дт | оплата отгруженного товара | оплата отгруженного товара (работ, услуг) |
| 62 | Кт | аванс, полученный от покупателя | как для аванса (ст. 487) |
| 58 | Дт | заем выданный | возврат займа и уплата процентов |
| 66, 67 | Кт | заем полученный | возврат займа и уплата процентов |
| 76 и прочие | ± | прочие расчеты | денежное требование по расчетам |

### 6.3. Зачет и уступка (plan)

1. По каждому контрагенту в работе: P — требования организации (Дт), N — долги организации (Кт). Зачет = min(P, N) — соглашение о зачете (ст. 410 ГК РФ). Гасятся сначала позиции той же природы, что у встречной стороны (товар↔товар, аванс↔аванс, заем↔заем), затем мелкие. Если в зачете есть авансы — в соглашение добавляется пункт о прекращении обязательства по поставке и переводе предоплаты в денежный долг.
2. Остаток долга организации (КЗ) → договор уступки: цедент — контрагент, цессионарий — Консолидатор, должник — организация.
3. Остаток требований организации (ДЗ) → договор уступки: цедент — организация, цессионарий — Консолидатор, должник — контрагент. Цена = номинал × % (по умолчанию 100%).
4. Если контрагент — сам Консолидатор: только зачет, остаток — собственный долг организации перед Консолидатором.
5. Цена уступленной ДЗ прекращается соглашением **ЗЦ** (зачет с Консолидатором) против долга организации перед ним (собственный + приобретенные Консолидатором требования к организации). ЗЦ = min(цена ДЗ + собственная ДЗ, долг). Итоговый долг перед Консолидатором = долг − ЗЦ.
6. Цена уступок КЗ — оплата Консолидатором деньгами до срока (`payDate`), кроме случая 6.4.
7. Нумерация: `{префикс}-З-01`, `{префикс}-Ц-01` (сначала КЗ по убыванию суммы, затем ДЗ), `{префикс}-ЗЦ-01`.

### 6.4. Пакет по нескольким организациям (runGroup)

Организации обрабатываются по порядку. Для каждой следующей организации операции с ранее обработанными берутся по номерам из их пакетов (`external`), документы не дублируются: зачет ↔ тот же зачет; уступка КЗ первой (цедент — вторая) ↔ уступка ДЗ второй с тем же номером; и наоборот. Если цедент — организация пакета, цена уступки гасится ее собственным ЗЦ (`offsetCedents`), а не деньгами.

### 6.5. Документы

- Договор уступки: предмет со ссылкой на перечень (таблица: основание, содержание требования, сумма), пункты про авансы (ст. 487) и займы (проценты) — только если такие позиции есть; переход права в момент подписания; гарантии цедента; цена и порядок оплаты (деньги до даты / зачет по ЗЦ / зачет по ЗЦ другой организации); передача документов; ответственность за действительность (не за исполнение); уведомление должника через подпись на договоре («Уведомлен об уступке, задолженность подтверждаю»); реквизиты и подписи.
- Соглашение о зачете: требования сторон таблицами, сумма зачета прописью, остатки после зачета, гарантии, акт сверки.
- Номера и даты договоров-оснований — пустые поля («№ ______ от ____________»), пока нет данных о договорах.

### 6.6. Готовность к ликвидации (verdict)

Выводы (по убыванию готовности): **Можно** → **Условно готово** → **Пауза** → **Не готово** → **Нет данных**.

Главное правило (от пользователя): **если остатки можно закрыть пакетом документов текущей датой, который не нужно визировать у сторон вне группы, — ЮЛ «Условно готово», а не «Не готово».**

| № | Условие | Вывод / что сделать |
|---|---|---|
| 0 | нет ИНН / нет собственной книги | «Нет данных»; показать, что за ЮЛ числится в книгах группы; выгрузить его базу |
| 1 | статус ЮЛ «Запрещено/Чужой» | «Не готово»: не цель обнуления |
| 2 | остатки с ВГО со статусом «Запрещено/Чужой» | «Не готово»: решение по статусу этих ВГО |
| 3 | внешняя КЗ: сальдо по контрагенту (все счета) ≤ −порога (100 000) | «Не готово»: перевод долга требует согласия (подписи) кредитора — погасить или перевести |
| 4 | неисполненные контракты: строки таблицы «Недогруз»; если таблица не загружена — отгрузки внешним покупателям (Дт 62 не-ВГО) за период ≥ порога | «Пауза»: исполнение контракта передать нельзя; неоплаченную ДЗ по нему уступить можно |
| 5 | ВГО-расчеты; встречные с внешним контрагентом (зачет заявлением, ст. 410 ГК РФ); внешняя ДЗ (уступка + уведомление должнику, ст. 382, 385 ГК РФ; опция «без подписи должника»); имущество на 03 | не блокируют: «Условно готово», в «Что сделать» — какие пакеты сформировать (ветки 1 и 2) |
| иначе | расчетов нет | «Можно» |

Если есть и блокеры (1–3), и пауза — вывод «Не готово». Документы, которые можно сделать сразу, все равно перечисляются в «Что сделать». План мероприятий с датами строится для «Можно» и «Условно готово».

**Таблица «Недогруз» — отчет «Анализ заказов клиентов»** (1С, отбор: «Не отгруженные по заказу», «Договор.Подписан = Да», при необходимости — дата заказа не ранее N). `EngineLiq.parseContracts(rows)` ищет заголовки по словам: «Заказ клиента.Организация» (наименование нашего ЮЛ, **без ИНН**), «Клиент», «Договор», «Срок исполнения», «Осталось отгрузить, сумма с НДС» (обязательны организация, договор и остаток), а также «Отгружено…», «Готов к отгрузке…», «Размещено у поставщиков…», «Не размещено у поставщиков…». Строки без организации и «Итого» пропускаются; дата отбора берется из строки «Отбор» шапки (`con.from`).
- **Привязка к ЮЛ** — `prepareContracts` по наименованию через `Engine2.innByName` (реестр: имя, «Название в 1С», алиасы; ключ наименования без формы и скобок «(бывш. …)»; затем реквизиты). Нестрогого сопоставления нет намеренно: бывают разные юрлица с похожими названиями. Не найденные организации — `con.unmatched`; чтобы привязать, добавьте наименование из отчета в колонку «Алиасы контрагента» реестра.
- **Госконтракт** — договор со словом «контракт» или номером закупки из 18–25 цифр (`GOV`). Остальные — прочие договоры.
- **Пауза** — у ЮЛ остаток к отгрузке по подписанным договорам ≥ порога (1 000 ₽): исполнение контракта передать нельзя, неоплаченную ДЗ — можно. Критерий отгрузок по Дт 62 при загруженном отчете отключается. В причине: сумма, число госконтрактов/прочих, последний срок, просрочка, крупнейшие.
- **Кнопка «Госконтракты»** (вкладка 3) → `govReport` / `buildGkXlsx`: по каждому ЮЛ реестра — «исполняются» (остаток по ГК ≥ порога) или «завершены» (прежнее «не применимо» сохраняется) + комментарий (сколько осталось, готово к отгрузке / размещено / не размещено у поставщиков, ближайший срок, просрочка, крупнейшие заказчики). Если в отчете есть несопоставленная организация, содержащая наименование ЮЛ, вывод «НЕ ОПРЕДЕЛЕНО». Результат — Excel с колонками для переноса в реестр по ИНН (SheetJS не сохраняет оформление, поэтому сам реестр программа не перезаписывает).
- Ограничение: в отчет попадают только заказы после даты отбора; более ранний госконтракт, еще не исполненный, в него не попадет — «завершены» означает «в отчете остатков нет».

Срок «по динамике» = остаток / (снижение за период / месяцев периода); если > 12 месяцев — не показывается. Документы для готовых ЮЛ формируются отдельно: ВГО — в ветке 1, внешние долги — в ветке 2.

Субсчета выбираются по знаку сальдо: 60 Дт→60.02, Кт→60.01; 62 Дт→62.01, Кт→62.02; 58→58.03; 66→66.03; 67→67.03; 76→76.09.

## 8. Правовые ориентиры (для текстов и подсказок)

ГК РФ: 382, 384, 385, 388, 390 (уступка), 392.3 (передача договора), 408 (исполнение), 410–412 (зачет), 413 (совпадение должника и кредитора), 415 (прощение), 487 (предоплата), 63–64 (ликвидация, очередность). ФЗ «Об ООО» ст. 58 (распределение имущества участникам). НК РФ: п. 1 ст. 155 (НДС при уступке), пп. 1 п. 3 ст. 284 (ставка 0% по дивидендам/квоте при доле ≥ 50% более 365 дней).

Остаток денег при ликвидации: расходы ликвидации → внешние кредиторы и налоги → ликвидационная квота участнику. Альтернативы «живым» деньгам: передача требования к Консолидатору участнику в составе квоты; присоединение к Консолидатору вместо ликвидации.

## 9. Подсказки пользователю: как получить данные в 1С (БП 3.0)

- **Лучший вариант:** по каждой базе 1С — регистр бухгалтерии «Журнал проводок», таблица «Остатки и обороты», группировки Организация → Счет → Субконто 1 (+ ИНН) → Субконто 2, период — квартал (например, 01.07–30.09), без отбора по организациям. Один файл на базу.

- **Анализ субконто «Контрагенты»**: Отчеты → Анализ субконто; период — с начала года по дату остатков; все организации; без отбора по счетам и комментарию; Показатели — только БУ (снять «Количество», «Валютная сумма»); Доп. поля — ИНН; группировка Организация → Контрагенты → Счет; сохранить .xlsx.
- **Универсальный отчет** — раздел 3.4 (сначала по 1–2 организациям как образец).
- **Работники**: анализ субконто «Работники организаций», счета 70/71/73/76, доп. поле ИНН.
- Период: брать с начала года — точнее оценка динамики.

## 10. Проверка качества

- Самопроверка (`EngineTest.run()` / кнопка на вкладке «Документация») — после любого изменения движка.
- На реальных выгрузках: контроль сумм (разобранные строки = «Итого» отчета), проводки обнуляют ВГО, совпадение результата при загрузке «обычных» и «полных» выгрузок одной базы, сверка со встречными книгами (расхождения выводятся, не скрываются).
- Документы: открыть 2–3 договора разных видов (поставка+аванс, заем, зачет с консолидатором) и проверить текст, падежи, таблицы.

## 11. Известные ограничения

- Формат «Регистр бухгалтерии» без ИНН организаций: ИНН подбирается по наименованию через реестр — организации, которых нет в реестре, в работу не попадают, пока их не добавят в реестр.
- При смешивании «Регистра бухгалтерии» и «Анализа субконто» одной базы организация берется из первого файла (повтор не складывается); разные базы лучше выгружать в одном формате.

- Субсчета 60/62/76 в анализе субконто свернуты — вид требования и НДС на 76 определяются эвристически; надежно — после поддержки универсального отчета.
- Нет договоров-оснований и дат — поля пустые.
- Должность «Руководитель» трактуется как «Генеральный директор».
- Нет учета работников, денег, имущества, налогов, капитала (кроме сч. 03) — пока нет источника.
- Расчет сроков — оценка, не прогноз.

Задумано: для незнакомого файла — автоопределение шапки, колонок (сальдо/обороты Дт/Кт, ИНН), иерархии (группировки Excel / отступы / шаблоны строк) и смысла уровней (код счета → счет; 10/12 цифр → ИНН; «№ … от …» → договор; ФИО → работник); предпросмотр дерева и контрольная сверка с «Итого»; кнопка «ОК» активна только при сходящейся сверке; формат хранится с «отпечатком» (заголовок + шапка).
3. **Панель «Что есть / чего не хватает»** — ✔ сделано: `EngineLiq.coverage(ctx)`: реестр, реквизиты (и у скольких ЮЛ из работы нет), долги с ИНН (и по скольким ЮЛ реестра нет выгрузки), договоры в основании, исполнение контрактов (недогруз), работники, деньги, имущество, налоги, капитал, обороты с внешними покупателями; у каждого пункта «?» с инструкцией по 1С.
4. **План ликвидации по каждому ЮЛ** — ✔ сделано (раздел 5.4). При наличии «Регистра бухгалтерии» план содержит реальные проверки по итогам счетов: работники (70, 71, 73), налоги и взносы (68, 69), деньги (50–57), имущество и запасы (01, 04, 08, 10, 20, 21, 26, 41, 43), финансовые вложения (58); без него — «не проверено» со ссылкой на панель. Эти шаги вывод готовности не меняют.
5. **Редактор правил и память решений** — ◐ частично: сохраняются (автоматически в браузере; кнопки «Скачать/Загрузить настройки») пороги, даты, опции, список статусов-блокеров (поле «фрагменты через |») и ручные «в работе» по контрагентам. **ИНН и наименования в настройках явно не хранятся** — ключи ручных решений хэшируются (`hk`), переопределение реквизитов контрагента не сохраняется. Не сделано: редактор текстов причин/действий/сроков, перезапись самого HTML (File System Access API). Привязка названий отчета к ЮЛ — через колонку «Алиасы контрагента» реестра.
6. **Договоры-основания в документах** — ✔ сделано: по формату «Регистр бухгалтерии» договоры берутся из субконто 2 **по счету** (`cp.cbyacc`) и попадают в колонку «Основание (договор)» договора уступки; для «Анализа субконто» — только если у контрагента не более 2 договоров; иначе остается шаблон «договор № ___ от ___». Служебное «Основной договор» не подставляется.
7. **Не делать без отдельного запроса:** внешнюю обработку 1С (.epf собрать без платформы нельзя; возможны исходники BSL + XML для «Загрузить внешнюю обработку из файлов», с проверкой на копии базы).

## 13. Рассмотренные и отложенные идеи (не реализованы)

- «Вертолеты» — круговые платежи ограниченной суммой между организациями для погашения встречных ДЗ/КЗ без зачета. Работали в ранней версии; после очистки НДС-строк на 76 почти все такие круги исчезли, остальное закрывается зачетами. Можно вернуть как вариант для случаев, где зачет юридически невозможен. Нужны от пользователя: лимит суммы, допустимые участники круга, форма документов.
- Продажа консолидированного портфеля требований покупателю бизнеса с дисконтом (покупатель как новый кредитор может простить долг) — модель была в ранней версии. Нужны от пользователя: дисконт по категориям требований, перечень исключений (в ранней версии — отдельный договор и 90% дисконт для одного контрагента), форма расчетов.
- Сопоставление названий отчета с ЮЛ: нестрогое сопоставление допускается только для «шумовых» слов и топонимов, код региона которых совпадает с началом ИНН кандидата (`Engine2.innByName`, справочник `REGION_NAMES`); все остальное — через «Алиасы контрагента».

## 14. Глоссарий

ВГО — внутригрупповые обороты/расчеты. ДЗ — дебиторская задолженность (нам должны). КЗ — кредиторская (мы должны). Консолидатор — единый кредитор группы, на которого переводятся требования. Цедент — кто уступает требование; цессионарий — кто получает; должник — кто должен. ЗЦ — соглашение о зачете цены уступленной ДЗ с Консолидатором. Книга — данные одной организации в выгрузке. Зеркало — сальдо с той же парой в книге контрагента. ОСВ — оборотно-сальдовая ведомость. Субконто — аналитика счета в 1С.
